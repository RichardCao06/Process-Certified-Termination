# Contributing

## Current project phase

The repository is in **P1**. Contributions may improve descriptive process review, taxonomy, annotation feasibility, observable trace infrastructure, synthetic fixtures, and reversible development tooling. They must not claim empirical effectiveness, access held-out/sealed material, or present draft annotation semantics as approved Gold.

## Change process

1. Link every change to a Work Order or Decision ID.
2. Use a feature branch; do not put substantive changes directly on `main`.
3. Separate normative changes from implementation changes when practical.
4. Run `make validate`.
5. State what changed, what did not change, tests run, risks, and unresolved human decisions.
6. Preserve original annotations and rejected taxonomy alternatives before adjudication or migration.

## Authority boundary

Agents may draft and implement reversible work. Human approval is required for annotation semantics, hard process violations, pilot design, empirical Gold, metrics, statistical thresholds, role assignments, sealed-data rules, model/harness freezes, online intervention, and external publication.

## Failure preservation

Do not delete failed runs, rejected alternatives, annotation disagreements, negative findings, or protocol conflicts. Corrections should be additive and traceable.
